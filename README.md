# Agent Lab for Pi

Цели пользователей → карточки персон → диалоги с агентом → оценки с доказательствами. Человек проверяет постановку до запуска и результаты после него. Всё происходит в Pi.

## Запуск

Нужен Node.js 22.19+.

```sh
npm ci
npm run build
npm run pi
```

В Pi выберите провайдера через `/login` и модель через `/model`, если они ещё не настроены. Пакет использует текущую модель Pi.

Начните сообщением:

> Подготовь проверку этого агента по @policy.md. Сформируй пять целей пользователей, карточки персон и метрики. Покажи черновик для моей проверки.

Для знакомства на встроенном сценарном примере:

> Подготовь демонстрацию Agent Lab.

Внутри демонстрации роли работают по готовому сценарию без модельных вызовов; обычное общение с самим Pi использует выбранного провайдера.

Затем откройте **`/agent-lab`**. Команда `/agent-lab ID` открывает конкретный эксперимент. Здесь находятся карточки, редактирование, человеческое подтверждение запуска, диалоги и результаты. Пакет пока распространяется локально; его можно подключить к другому Pi через `pi install /absolute/path/to/pi-agent-lab` после сборки.

## Четыре шага

| Шаг | Содержимое карточки |
|---|---|
| Цель | Что хочет получить пользователь, критерий успеха, исходные требования и предположения |
| Пользователь | Персона, характеристики, известные факты, поведение и первая реплика |
| Диалог | Сообщения, решения симулятора, вызовы инструментов, результаты и состояние |
| Оценка | Объективные проверки, предварительные оценки по рубрикам, ссылки на события и замечания человека |

Карточка пользователя превращается в обычный промпт. Следующая реплика зависит от фактического ответа агента. Внутреннее состояние и ожидаемые оценки не передаются симулятору.

Простой запуск поддерживает одну цель и одного пользователя. По умолчанию готовится пять сценариев. Набор для сравнения версий не является обязательным условием обычной проверки агента.

## Участие человека

**Перед запуском:** просмотрите агента, источники, цели, персоны, предположения и критерии. Измените нужные поля в карточках или попросите Pi подготовить правку. Подтверждение в нативном интерфейсе относится к точной версии всего набора. Изменённый черновик требует нового подтверждения.

**После диалогов:** откройте оценки и события, проверьте поведение симулятора. Можно сохранить собственную оценку для диалога, объективной проверки или метрики, указав объяснение. Исходные результаты сохраняются; замечания человека дописываются отдельно. Завершение проверки фиксируется отдельным подтверждением.

В основном процессе проверяется одна неизменная версия агента. Автоматическая оптимизация не запускается. Для повторного эксперимента с новыми условиями нужен новый черновик; завершённые диалоги не переписываются.

## Что означают оценки

- **Код:** конечное состояние записи, наличие/отсутствие и число вызовов инструмента, чтение нужной записи до изменения, буквальное наличие текста.
- **Модель:** результат `pass`, `fail` или `unknown` по заранее утверждённой рубрике, объяснение и ссылки на конкретные события. Метрики агента и симулятора разделены.
- **Человек:** отдельные оценки и комментарии с сохранением истории.
- **Расходы:** число сообщений, длительность, модельные вызовы, токены и известная стоимость. В расходы входят симулятор и оценщик.

Без объективных проверок результат диалога обозначается `ungraded`; оценки по рубрикам показываются отдельно. Ошибка оценщика не превращается в ошибку агента. Ссылки на несуществующие события, пропущенные или повторённые метрики отклоняются.

LLM-оценки предварительные. Соответствие JSON-схеме не доказывает правильность смысла, реалистичность персоны или независимость сценариев. Человеческая проверка помогает выявлять эти ошибки; качество оценщика нужно измерять по размеченным реальным примерам. Синтетические результаты не доказывают качество продукта с реальными пользователями.

`maxFollowUps` ограничивает дополнительные реплики пользователя. Ноль означает один запрос, один — одну возможность уточнить данные или изменить намерение. Последняя непустая реплика доставляется агенту даже при флаге завершения. Выполнение лимита не означает достижения цели.

## Поддерживаемые агенты и материалы

Можно передать существующий `AgentSpec`: имя, инструкции и список разрешённых инструментов. Поддерживается разговорный агент без инструментов. Зарегистрированный тестовый контур предоставляет `search_materials`, `lookup_record`, `update_record`; они работают с предоставленными материалами и изолированными записями.

Для подключения конкретного внешнего агента понадобится адаптер к его локальному входу или API с правилами сессии и сброса состояния. Универсального подключения CRM, Langflow или произвольного сервиса пока нет. Для настоящего пилота нужны один выбранный агент, golden set, метрики и разрешённые обезличенные диалоги. Преимущество реактивного симулятора над статическими и scripted-тестами ещё нужно измерить.

Методика встроена в [скилл](skills/agent-builder/SKILL.md), промпты ролей и код. Внутренние роли не имеют браузера, shell и файловых инструментов и не загружают методику по ссылкам. Исследования и план — в [docs/PLAN.md](docs/PLAN.md).

## Артефакты и проверка

Артефакты лежат в `.agent-lab` проекта: полный JSON, журнал событий, экспорт агента и отчёт. Материалы и диалоги сохраняются открытым текстом с ограниченными правами файлов; при live-запуске необходимое содержимое передаётся выбранному провайдеру.

```sh
npm test
node dist/cli.js status
node dist/cli.js prepare --input task.json
node dist/cli.js export --id EXPERIMENT_ID --output evidence.json
```

CLI `build` и `prepare` сохраняют черновик. Запуск нового процесса оценки подтверждается в интерфейсе Pi. `task.json` содержит `task`, `materials: [{name, content}]`, `mode: "live"`, `settings: {provider, model}`, необязательный `existingAgent` и `scenarioCount` от 1 до 10.

Старая механическая демонстрация сравнения доступна отдельно через `npm run demo -- --data-dir .context/demo`. Она использует scripted-роли и проверяет исправление отсутствующего инструмента; её оценки не являются доказательством качества LLM.

Один каталог обслуживает один процесс и одну активную операцию. Сохранение атомарное. После аварии проверьте остановку процесса, удалите оставшийся `.agent-lab/.lock` и перезапустите: активные прогоны будут помечены как прерванные. Черновики и результаты, ожидающие человека, сохраняются между сессиями.
