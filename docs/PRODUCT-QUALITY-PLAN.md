# Agent Lab: законченный цикл проверки агента

План объединяет пользовательский аудит и три независимых разбора: gstack `plan-eng-review`, mattpocock `improve-codebase-architecture` и `thermo-nuclear-code-quality-review`.

Цель этой итерации: пользователь подключает агента, понимает предложенные проверки, исправляет карточки без потерь, запускает диалоги, находит основание провала и сравнивает повтор после исправления. Отчёт должен передавать те же доказательства человеку, который не присутствовал при запуске.

## Выбранное решение

Развиваем существующий Pi-интерфейс и автономный HTML-отчёт. ExperimentLab владеет изменениями и переходами фаз, ExperimentStore — файлами и блокировкой писателя, расчёты доказательств остаются чистыми. Общий снимок связывает запись, сравнение и журнал для всех способов экспорта.

| Работа | Результат для пользователя | Критерий приёмки |
|---|---|---|
| Безопасное редактирование | Правка второй карточки сохраняет остальные. Удаление названо явно. | `scenarios` обновляет/добавляет по id; `removeScenarioIds` удаляет. Дубли, конфликт, неизвестное удаление, stale hash и невалидный итог ничего не сохраняют. |
| Понятный разбор | Результат агента, источник оценки, полнота выполнения и ручные вердикты видны отдельно. | Нерешённый провал блокирует завершение; `unknown` не закрывает очередь. Старые записи с незавершённым разбором показываются честно. Smoke failure не снижает достоверность самого измерения. |
| Стабильные доказательства | Повтор всегда экспортируется вместе со сравнением с родителем. | HTML, Markdown, JSON и Pi используют один снимок. Выбранная вручную база подписана; отсутствующий родитель объясняется, текущая запись доступна. |
| Разбор изменений | Из списка исправлений/регрессий можно прочитать ответы до и после. | Пары берутся из проверенного сопоставления scenario/mode/repeat; видны версии, критерии и идентификаторы трасс. Несравнимые данные не превращаются в улучшение. |
| Восстановление истории | Один повреждённый файл не закрывает исправные прогоны. Экспорт работает при открытой доске. | Чтение без writer lock; диагностика повреждённых файлов; единственный писатель; восстановление только доказанно мёртвого владельца с защитой от гонок. |
| Ранние ошибки подключения | Ошибка команды или пути обнаруживается до модельной подготовки. | Только статическая проверка executable/PATH/cwd/файлов/env; ни одного запроса испытуемому до утверждения. Полный инфраструктурный отказ ведёт к исправлению подключения. |
| Точные проверки | Буквальное равенство ответа проверяет код. | `answer_equals` проверяет последний ответ с сохранением регистра, пробелов и переносов; внешний генератор может использовать наблюдаемые текстовые проверки, но не выдуманные state/tool проверки. |
| Удобный Pi | Демо доступно из списка; ошибка поля сохраняет ввод; прогресс и экспорт видны на доске. | Невалидное число → понятная ошибка → исправление в том же редакторе. В 80×24 видна первая реплика; есть положение прокрутки, открытие отчёта и переход к сравнению. |

## Порядок и ответственность

1. Зафиксировать контракты правки, вычисляемого статуса разбора и сопоставленных попыток; добавить проверки сохранности.
2. Параллельно реализовать хранение/снимок/отчёты и статическую проверку подключения/точный grader. Владение файлами разделено между агентами.
3. Перевести Pi на общие контракты, компактное представление и редактор с повторным вводом. Обновить README и глоссарий.
4. Проверить полный цикл на настоящем Pi и локальном адаптере: демо → правка с ошибкой → запуск → вердикты → завершение → повтор → сравнение → экспорт → повторное открытие. Отдельно проверить отмену и сбои.
5. Завершить goal после прохода тестов, проверки типов, упаковки и пользовательского прохода; сохранить воспроизводимые свидетельства.

## Границы решения

Сохраняем заморозку измерений, атомарные записи, отдельные исходные проверки/оценки/аннотации, отмену и контроль сопоставимости. Дополнительных зависимостей не требуется. Веб-приложение, совместная работа, CI-режим с новой моделью утверждения, произвольные graders и параллельный runner требуют отдельной подтверждённой потребности.

Этот проход проверяет качество инструмента. Качество бизнес-агента и переносимость синтетических результатов на реальных пользователей потребуют пилота с материалами владельца. «Уровень OpenAI» здесь — планка удобства и аккуратности, а не заявленное соответствие внешнему стандарту.

## Проверка результата

Реализовано 12 сентября 2026: все восемь работ из таблицы. Базовые 139 тестов расширены до 162; все проходят. `npm run typecheck`, `npm test`, `npm pack --dry-run` и `git diff --check` завершились успешно. Новых зависимостей нет.

В настоящем Pi пройден цикл: демо с тремя карточками → ошибка числа и исправление без потери карточек → 0/3 → блокировка завершения до вердиктов → разбор → повтор → включение `update_record` → 3/3 → парные ответы → экспорт → открытие в браузере. После переоткрытия экспорт сохраняет сравнение без предварительного посещения раздела сравнения. В терминале 80×24 первая реплика и ответ видны одновременно. Завершение разбора возвращает в обзор; устаревшие уведомления не дублируются в истории Pi.

Проверены живой генератор и настоящий локальный Python-адаптер: буквальное требование становится `answer_equals`, смысловое — рубрикой. Точный ответ прошёл кодовую проверку, fidelity — модельную. Отмена медленного Node-адаптера после второго запроса сохранила пять событий, оставила `cancelled` без ложных оценок и завершила процесс. Эти проверки использовали пять модельных вызовов, оценка SDK — $0.103995.

CLI экспортирует при открытой доске. Регрессии покрывают повреждённую историю, гонку четырёх процессов при восстановлении lock, атомарность редактирования, неразобранные провалы, обновление сравнения и передачу выбранной пары в обсуждение. Финальный независимый review не нашёл существенных замечаний к исправленному пути обновления интерфейса.
