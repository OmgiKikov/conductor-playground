Дата: 12 сентября 2026 года. Среда: macOS, Node.js 22.22.3, Pi 0.85.1. Исследование и продуктовые решения: [RESEARCH-AND-PRODUCT-DIRECTION.md](RESEARCH-AND-PRODUCT-DIRECTION.md).

## Результат

**168/168 тестов проходят. Проверка типов и сборка проходят.** Нативный цикл с внешним Python-процессом выполнен через Pi: запуск шести диалогов, разбор, повтор, изменение подключения, ещё шесть диалогов, сравнение и экспорт. В этой новой внешней проверке модельные вызовы лаборатории не использовались. Ответы выдавал управляемый тестовый процесс.

Это отдельная итерация после предыдущих трёх инженерных ревью. Её исходная граница сохранена в `.context/research/starting.patch`. Ранее исправленные проблемы не считаются новыми находками этого исследования.

## Управляемый внешний сценарий

Две синтетические карточки требуют буквальный ответ `ACCEPTED`. В тестовом `agent.py` на третьей попытке второй карточки намеренно возвращается `REJECTED`; аргумент `--fixed` отключает эту ошибку. Счётчик находится в изолированной QA-папке. Это специально созданный стенд для проверки интерфейса и измерений, а не модель поведения реального клиента.

Первый черновик подготовлен с заранее заданными карточками через тестовый runtime. Новая LLM-генерация карточек в этом сценарии не проверялась. Дальнейшие действия выполнены в обычном Pi с установленным расширением и настоящим адаптером command:

1. Проверка карточек и подтверждение запуска.
2. Шесть реальных запросов к Python-процессу: 5 успешных, 1 неуспешный.
3. Чтение всех ответов и проверок; отдельная отметка к провалу через `v` со ссылкой на ответ `#1` и обозначением `Codex QA, synthetic fixture; not owner approval`.
4. Завершение тестового разбора и `r` для нового черновика.
5. Добавление `--fixed`, изменение версии на `qa-fixed`, запуск того же набора.
6. Ещё шесть запросов: все успешные. Сопоставлены 6/6 пар; исправлена 1 карточка, регрессий 0.
7. Завершение разбора и экспорт после повторного открытия, без потери ссылки на родительский прогон.

## Автоматические проверки

Новые регрессии проверяют обе стороны расхождения (`auto pass / human fail` и `auto fail / human pass`), пересмотр отметки, независимость отметок на разных критериях, отсутствие подмены ошибок симулятора ошибками агента, неизвестный результат отменённой попытки, пропуски и дубли повторов, сохранение исходных измерений, выбор изменившейся пары и безопасное отображение заметки в экспортах.

Проверки редактора подтверждают сохранение пробелов и буквального `$(...)` внутри argv без исполнения оболочкой, сохранение других параметров подключения, повтор ввода после неправильного URL и переход к полному JSON для представлений аргументов, которые нельзя надёжно редактировать построчно.

Выполнены `npm test`, `npm run typecheck`, проверка отчётов после последней правки отображения пустой рубрики и `npm pack --dry-run`. Браузерная проверка выявила отображение `0/0` при отсутствии рубрик; оно заменено на «Нет оценок» с пояснением причины.

## Где лежат локальные доказательства

Папка `.context` исключена из Git; перечисленные файлы доступны в этой рабочей копии и не входят в опубликованный пакет:

- `.context/research/pi-before.txt` и `pi-after.txt` — записи нативного прохождения. При большом объёме перерисовок вывод PTY мог усекаться; ключевые экраны и сохранённые записи проверены отдельно.
- `.context/research/human-review-before.json` — исходная сводка с невидимым ручным провалом.
- `.context/research/qa-summary.json` — результат отдельной машинной проверки сохранённых прогонов.
- `.context/research/verify-research-qa.ts` — проверка этих QA-записей без новых запусков агента.
- `.context/research/before-report.html`, `after-report.html`, `human-review-report.html` — автономные отчёты.
- `.context/research/qa-project/.agent-lab/` — исходные прогоны и экспорты, созданные через интерфейс.
- `.context/research/sources/code-manifest.json` — исходные GitHub URL, commit SHA и хеши загруженных файлов.
- `.context/research/test-output.txt`, `typecheck-output.txt`, `report-test-output.txt`, `package-output.txt` — вывод проверок.

Результаты 5/6 и 6/6 подтверждают правильность работы со специально внедрённым сбоем. Они не доказывают качество произвольного агента, реалистичность симулятора или коммерческую полезность Agent Lab. Проверка на независимых пользователях и продуктовых данных остаётся следующей задачей исследования.
